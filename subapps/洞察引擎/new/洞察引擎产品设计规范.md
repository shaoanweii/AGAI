# 洞察引擎产品设计规范

## 1. 设计定位

洞察引擎是面向企业 VOC 场景的数据智能治理平台，产品设计应优先服务于数据接入、数据治理、规则配置、模型处理、审核反馈、质量监控和系统配置等高频后台工作。

整体设计应体现：

- 专业、稳定、可信。
- 面向运营和数据治理人员的高效率操作。
- 面向复杂数据链路的可追踪、可解释、可回放。
- 支持多客户、多项目、多渠道、多权限的产品化配置。

不建议采用营销化、展示型、大面积装饰型设计。界面应以表格、筛选、树、表单、流程、状态、监控图表为核心。

## 2. 产品设计原则

### 2.1 数据优先

所有页面优先保证数据可读、可查、可筛、可追踪。视觉设计服务于数据密度和操作效率。

### 2.2 配置产品化

客户、项目、渠道、规则、模型、标签、处理流程等差异应通过配置承载，不通过页面或代码硬编码体现。

### 2.3 链路可解释

原始数据、结果数据、异常数据、处理记录、审核记录都应能查看完整处理链路。

### 2.4 异常可处理

所有异常不只展示状态，还要提供原因、影响范围、样本、处理入口和关闭机制。

### 2.5 权限可感知

用户只看到授权客户、项目、渠道、菜单和操作。无权限操作不展示，特殊场景可禁用并提示原因。

### 2.6 审核反馈闭环

人工审核、纠错、新词处理、未归一观点处理都应沉淀为反馈样本，而不是一次性操作。

## 3. 信息架构规范

### 3.1 一级菜单

一级菜单固定为：

1. 主控台
2. 数据资产
3. 数据接入
4. 处理流水线
5. 知识中心
6. 规则中心
7. 审核反馈
8. 监控中心
9. 系统管理

### 3.2 菜单设计规则

- 一级菜单承载业务域。
- 二级菜单承载明确业务对象。
- 不建议出现三级菜单；复杂页面通过页签、左树右表、抽屉承载。
- 菜单名称使用业务语言，不使用技术语言。
- 同一业务对象只出现在一个主入口，避免多处维护。

### 3.3 推荐布局

```text
左侧菜单 + 顶部标题/页签 + 主内容区
```

主内容区常用结构：

```text
页面标题/页签
筛选区
操作区
数据表格/流程图/监控图表
分页/明细抽屉/弹窗
```

## 4. 页面类型规范

### 4.1 列表管理页

适用页面：

- 数据源管理
- 字段映射
- 接入任务
- 流程配置
- 任务管理
- 标签体系
- 标准观点
- 关键词库
- 规则中心各页面
- 客户管理
- 项目管理
- 模型配置
- 账号管理
- 角色管理

页面结构：

```text
筛选区
操作按钮区
列表表格
分页
新增/编辑弹窗或抽屉
```

必备能力：

- 查询
- 重置
- 新增
- 编辑
- 详情
- 启用/禁用
- 删除或归档
- 批量操作
- 导出，按权限控制

### 4.2 数据查询页

适用页面：

- 原始数据
- 结果数据
- 异常数据
- 处理记录
- 接入记录

页面结构：

```text
筛选区
状态统计条
数据列表
详情抽屉
证据链/处理链路
```

必备能力：

- 多条件筛选
- 列表分页
- 查看详情
- 查看处理链路
- 查看异常原因
- 重跑或重新处理，按权限控制
- 加入反馈样本，按场景控制
- 导出

### 4.3 流程配置页

适用页面：

- 处理流水线 / 流程配置
- 处理流水线 / 后处理配置

页面结构：

```text
流程基础信息
节点配置区
节点参数区
测试区
发布/保存区
```

必备能力：

- 新建流程
- 编辑流程
- 添加节点
- 调整节点顺序
- 配置节点参数
- 测试流程
- 查看版本
- 发布/停用/回滚

### 4.4 审核处理页

适用页面：

- 纠错审核
- AI低置信审核
- 新词处理
- 未归一观点

页面结构：

```text
审核筛选区
待审核列表
审核详情
原结果 / 建议结果 / 人工结果对比
审核操作区
```

必备能力：

- 查看原始数据
- 查看系统结果
- 查看模型/规则/后处理证据
- 通过
- 修改通过
- 驳回
- 填写原因
- 生成反馈样本

### 4.5 监控看板页

适用页面：

- 数据质量监控
- 处理链路监控
- 标签质量监控
- 模型质量监控
- 后处理质量监控

页面结构：

```text
全局筛选
核心指标卡
趋势图
分布图
异常列表
样本明细
```

必备能力：

- 客户/项目/渠道/时间筛选
- 指标趋势查看
- 异常样本查看
- 告警规则跳转
- 异常事件跳转
- 导出明细

## 5. 筛选区规范

### 5.1 常用筛选项

不同页面可按需组合以下筛选项：

| 筛选项 | 适用场景 |
|---|---|
| 客户 | 所有多租户数据和配置页面 |
| 项目 | 项目化配置、数据查询、监控页面 |
| 渠道 | 数据资产、数据接入、知识、规则、监控 |
| 时间范围 | 数据、记录、监控、审核、审计 |
| 状态 | 所有配置和任务页面 |
| 关键词 | 数据、知识、规则、审核页面 |
| 品牌/车系 | VOC 汽车业务相关页面 |
| 标签体系 | 结果数据、标签质量、知识中心 |
| 任务类型 | 处理流水线、模型、监控 |
| 处理状态 | 数据资产、处理记录、监控 |
| 审核状态 | 审核反馈相关页面 |

### 5.2 筛选交互

- 默认展示 1 行核心筛选项。
- 次要筛选项收起到“展开筛选”。
- 查询按钮使用主按钮。
- 重置按钮使用默认按钮。
- 日期范围默认最近 7 天或最近 30 天，按页面业务决定。
- 所有筛选条件重置后回到默认客户/项目权限范围。

## 6. 表格规范

### 6.1 列表字段顺序

推荐顺序：

1. 选择框
2. 序号
3. 核心名称/数据 ID
4. 所属客户/项目
5. 业务属性
6. 状态
7. 质量/统计指标
8. 创建人/更新人
9. 创建时间/更新时间
10. 操作

### 6.2 操作列规范

常用操作：

- 详情
- 编辑
- 复制
- 启用/禁用
- 删除/归档
- 测试
- 发布
- 查看记录
- 查看样本

当操作超过 3 个时，使用“更多”下拉。

### 6.3 状态展示

状态必须使用文字 + 颜色，不只依赖颜色。

常用状态：

| 状态 | 颜色建议 |
|---|---|
| 正常/成功/启用/通过 | 绿色 |
| 待处理/处理中/待审核 | 蓝色 |
| 预警/低置信/部分失败 | 橙色 |
| 异常/失败/驳回 | 红色 |
| 禁用/归档/已关闭 | 灰色 |

## 7. 表单规范

### 7.1 新增/编辑表单

表单应使用弹窗或抽屉：

- 字段少于 8 个：弹窗。
- 字段较多或需要分组：抽屉。
- 涉及流程、规则、后处理配置：页面级编辑或大抽屉。

### 7.2 表单分组

复杂表单建议按以下分组：

```text
基础信息
适用范围
业务配置
执行策略
异常策略
状态与备注
```

### 7.3 必填校验

常见必填字段：

- 名称
- 编码
- 所属客户
- 所属项目
- 适用渠道
- 状态
- 规则条件
- 处理策略
- 负责人

### 7.4 编码规范

配置类对象建议都具备：

- 名称：业务可读。
- 编码：系统唯一。
- 描述：解释用途。
- 状态：启用/禁用。

## 8. 详情页规范

### 8.1 数据详情

原始数据和结果数据详情必须包含：

- 基础信息
- 原始内容
- 渠道信息
- 品牌车系信息
- 标签/观点/情感/关键词结果
- 处理链路
- 异常信息
- 审核/纠错记录

### 8.2 配置详情

规则、知识、流程、模型配置详情必须包含：

- 基础信息
- 适用范围
- 配置内容
- 引用关系
- 版本信息
- 操作记录
- 命中样本或执行记录

### 8.3 处理链路详情

处理记录详情必须展示：

- 接入节点
- 字段映射节点
- 数据规则节点
- 模型任务节点
- 后处理节点
- 审核节点
- 入库节点

每个节点展示：

- 节点名称
- 执行状态
- 开始时间
- 结束时间
- 耗时
- 输入摘要
- 输出摘要
- 异常原因

## 9. 后处理配置设计规范

### 9.1 后处理节点类型

建议支持：

- 输出结构化
- 标签映射
- 标准观点归一
- 关键词清洗
- 情感修正
- 置信度计算
- 冲突检测
- 规则校验
- 敏感信息处理
- 低置信分流
- 异常兜底

### 9.2 后处理页面要求

后处理配置页面必须支持：

- 节点配置
- 流程编排
- 输入输出字段配置
- 节点测试
- 流程测试
- 失败策略
- 版本管理

### 9.3 后处理结果展示

结果数据详情中必须展示：

- 模型原始输出
- 后处理前结果
- 后处理后结果
- 改动字段
- 转人工原因
- 后处理失败原因

## 10. 审核反馈设计规范

### 10.1 审核动作

统一审核动作：

- 通过
- 修改通过
- 驳回
- 忽略，适用于新词或未归一观点

### 10.2 审核原因

驳回和修改通过必须填写原因。

原因可包括：

- 标签错误
- 观点错误
- 情感错误
- 关键词错误
- 场景错误
- 模型低置信
- 规则冲突
- 数据质量问题
- 其他

### 10.3 反馈样本

审核后的反馈样本必须记录：

- 原始数据
- 系统结果
- 人工结果
- 差异字段
- 反馈原因
- 处理人
- 处理时间
- 来源模块
- 是否进入评测样本

## 11. 监控中心设计规范

### 11.1 指标卡

监控页顶部使用指标卡，最多 8 个。

指标卡包括：

- 指标名称
- 当前值
- 环比/同比
- 状态
- 点击后跳转明细

### 11.2 图表

推荐图表：

- 趋势类：折线图
- 分布类：柱状图
- 占比类：环图或堆叠柱
- 排名类：横向柱图
- 异常类：表格优先

### 11.3 异常明细

每个监控页面都应提供异常明细列表，字段至少包括：

- 异常对象
- 异常类型
- 当前值
- 阈值
- 影响范围
- 触发时间
- 状态
- 处理人
- 操作

## 12. 告警事件设计规范

### 12.1 告警等级

| 等级 | 说明 |
|---|---|
| 严重 | 影响核心链路或大量数据 |
| 高 | 影响部分客户/项目或关键指标 |
| 中 | 需要关注但不阻断业务 |
| 低 | 提醒类问题 |

### 12.2 告警状态

- 待确认
- 处理中
- 已解决
- 已忽略
- 已关闭

### 12.3 告警处理动作

- 确认
- 分派
- 查看样本
- 填写处理结论
- 关闭
- 忽略

## 13. 权限设计规范

### 13.1 权限层级

产品应支持：

- 菜单权限
- 按钮权限
- 客户权限
- 项目权限
- 渠道权限
- 品牌车系权限
- 标签权限
- 导出权限
- 审核权限
- 配置发布权限

### 13.2 权限默认规则

- 无客户权限，不展示该客户数据。
- 无项目权限，不展示该项目配置和数据。
- 无导出权限，不展示导出按钮。
- 无审核权限，不展示审核操作。
- 无发布权限，不展示发布/回滚操作。

## 14. 命名规范

### 14.1 菜单命名

- 使用 2-6 个汉字为宜。
- 避免技术词。
- 保持对象一致。

示例：

- 数据源管理
- 字段映射
- 后处理配置
- 标签质量监控

### 14.2 状态文案

统一使用：

- 启用 / 禁用
- 成功 / 失败
- 待处理 / 处理中 / 已处理
- 待审核 / 通过 / 修改通过 / 驳回
- 正常 / 预警 / 异常

### 14.3 操作文案

统一使用：

- 新增
- 编辑
- 删除
- 复制
- 详情
- 启用
- 禁用
- 测试
- 发布
- 回滚
- 导出
- 重跑

## 15. 视觉规范

### 15.1 色彩

建议延续现有系统风格：

| 类型 | 颜色 |
|---|---|
| 主色 | #1677FF |
| 品牌深色 | #0B457F |
| 页面背景 | #EAF3FF / #F5F7FA |
| 主要文字 | #1F2733 |
| 次要文字 | #5F6A7A |
| 辅助文字 | #929AA6 |
| 边框 | #DFE2E8 / #EBEDF0 |
| 成功 | #14CA64 |
| 警告 | #FAB007 |
| 错误 | #FF5959 |

### 15.2 字体

- 页面标题：20px / 600
- 模块标题：16px / 600
- 正文和表格：14px / 400 或 500
- 辅助说明：12px / 400

### 15.3 间距

- 页面主内容 padding：24px
- 卡片 padding：16px 或 24px
- 表单项间距：16px
- 按钮间距：8px
- 表格与分页间距：16px 或 24px

### 15.4 圆角

- 常规卡片：4px
- 表单输入：4px
- 弹窗/抽屉：4px 或 6px
- 状态标签：2px 或 4px

## 17. 空态、加载与错误

### 17.1 空态

空态文案：

- 暂无数据
- 暂无匹配结果
- 暂无异常数据
- 暂无待审核任务

如用户有新增权限，可显示新增按钮。

### 17.2 加载

以下操作必须有 loading：

- 查询
- 保存
- 删除
- 导出
- 测试
- 发布
- 重跑
- 审核提交

### 17.3 错误

错误提示应明确说明：

- 哪个对象失败
- 为什么失败
- 用户可以怎么处理

示例：

- 保存失败：规则编码已存在。
- 发布失败：后处理流程中存在已禁用节点。
- 重跑失败：原始数据缺少必填字段。

## 18. 产品化配置规范

所有核心能力都应支持客户/项目维度配置：

- 数据源
- 字段映射
- 处理流程
- 后处理配置
- 标签体系
- 标准观点
- 关键词库
- 数据规则
- 业务规则
- 监控规则
- 模型配置
- 权限配置

配置优先级建议：

```text
项目配置 > 客户配置 > 系统默认配置
```

## 19. 审计规范

以下操作必须记录审计：

- 登录/退出
- 数据导出
- 数据重跑
- 规则新增/编辑/删除/发布
- 流程新增/编辑/发布/回滚
- 后处理配置变更
- 模型配置变更
- 审核通过/驳回
- 权限变更
- 客户/项目配置变更

审计字段：

- 操作对象
- 操作类型
- 操作前内容
- 操作后内容
- 操作人
- 操作时间
- 操作原因
- IP 或来源，若可获取

## 20. 交付验收标准

### 20.1 信息架构验收

- 一级菜单不超过 9 个。
- 二级菜单命名清晰。
- 每个二级菜单有明确业务对象。
- 不出现重复入口。

### 20.2 页面体验验收

- 列表页具备筛选、分页、详情和状态展示。
- 配置页具备新增、编辑、启停和校验。
- 审核页具备对比、原因和反馈沉淀。
- 监控页具备指标、趋势、异常明细。

### 20.3 产品化验收
