# 旅程分析接口需求

- 模块：报表服务 / 场景分析
- 接口分层：Controller / Service / ServiceImpl / Mapper
- 备注：占位文档，后续根据业务补充详细入参、回参与SQL说明。

#### 各年龄段占比接口
- 数据范围：数据产生时间(data_create_time)范围内业务宽表VocSoundsEntity（voc_sentiment_annotations_results_v）的数据
    - 入参：
        - 公共查询条件（ExtendComQueryModel）
    - 回参：(集合数组)
        - title ：年龄段 
        - value : 用户数量
        - percent : 占比
        - valueMoM : 环比
        - valueYoY : 同比
- 说明：
    - 根据入参中的开始/结束时间查询data_create_time范围内的数据
    - 年龄段分组：18-25岁,25-30岁,30-40岁,40岁以上 
    - 要用resources/mapper/ReportCommonMapper.xml中的common_find_user_age补全年龄段占比
    - 顺序要用resources/mapper/ReportCommonMapper.xml中的common_find_user_age_order补全年龄段顺序

#### 旅程细化分析接口
- 数据范围：数据产生时间(data_create_time)范围内业务宽表VocSoundsEntity（voc_sentiment_annotations_results_v）的数据
    - 入参：
        - 公共查询条件（ExtendComQueryModel）
    - 回参：(集合数组)
        - 标签名称 (全旅程客户标签x级)
        - 标签编码 (全旅程客户标签编码x级)
        - 标签层级 (1/2/3/4)
        - value : 负面率/提及量
        - valueAvg : 负面率/提及量 均值
        - valueMoM : 负面率/提及量 环比
        - valueYoY : 负面率/提及量 同比
- 说明：
    - 根据入参中的开始/结束时间查询data_create_time范围内的数据
    - 当ExtendComQueryModel中dataType为mention 提及量时 要value 要按照提及量进行排序，
    - 当ExtendComQueryModel中dataType为negative_rate 负面率时，标签的顺序要按照这个顺序来：认知,选择,购买,使用,维保,再购
    - sql中查询的 标签名称,标签编码,标签层级字段 可以根据入参中的：
    - tag1Code,tag2Code,tag3Code,tag4Code动态的传入 如果tag1Code不为空时则 标签名称,标签编码,标签层级字段对应的字段为：cj_tag_first,cj_tag_first_code,1
    - 如果tag2Code不为空时则 标签名称,标签编码,标签层级字段对应的字段为：cj_tag_second,cj_tag_second_code,2
    - 如果tag3Code不为空时则 标签名称,标签编码,标签层级字段对应的字段为：cj_tag_three,cj_tag_three_code,3
    - 都为空是则用cj_tag_first,cj_tag_first_code,1 判断在sql 完成
