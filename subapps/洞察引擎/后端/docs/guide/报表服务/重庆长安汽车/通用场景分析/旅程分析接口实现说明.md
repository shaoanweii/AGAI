# 旅程分析接口实现说明

## 概述

根据需求文档完成了旅程分析模块的所有接口开发，包括Controller、Service、ServiceImpl、Mapper和相关的VO类。

## 实现的接口列表

### 1. 各年龄段占比接口
- **接口路径**: `/journey-analysis/getAgeDistribution`
- **功能**: 统计不同年龄段用户的占比情况
- **返回字段**: 年龄段、用户数量、占比、环比、同比
- **特点**: 使用ReportCommonMapper.xml中的common_find_user_age补全年龄段

### 2. 所在区域占比接口
- **接口路径**: `/journey-analysis/getRegionDistribution`
- **功能**: 统计用户所在省份的TOP5分布
- **返回字段**: 省份名称、省份编码、用户数量、占比、环比、同比
- **特点**: 只返回TOP5省份数据

### 3. 用户性别占比接口
- **接口路径**: `/journey-analysis/getGenderDistribution`
- **功能**: 统计用户性别分布情况
- **返回字段**: 性别、用户数量、占比、环比、同比
- **特点**: 使用common_find_user_gender补全性别分类

### 4. 用户类型占比接口
- **接口路径**: `/journey-analysis/getUserTypeDistribution`
- **功能**: 统计用户类型分布情况
- **返回字段**: 用户类型、用户数量、占比、环比、同比
- **特点**: 使用common_find_user_type补全用户类型（普通用户、车主客户、会员客户、售后客户）

### 5. 用户关注场景TOP10接口
- **接口路径**: `/journey-analysis/getFocusSceneTop`
- **功能**: 统计用户关注的场景TOP10
- **返回字段**: 场景名称、用户数量、环比、同比
- **特点**: 返回TOP10场景数据

### 6. 发声用户TOP5接口
- **接口路径**: `/journey-analysis/getVoiceUserTop`
- **功能**: 统计发声最多的用户TOP5
- **返回字段**: 用户名、用户ID、提及量、负面率、环比、同比
- **特点**: 按提及量排序，返回TOP5用户

### 7. 旅程细化分析接口
- **接口路径**: `/journey-analysis/getJourneyDetailAnalysis`
- **功能**: 分析全旅程客户标签的详细数据
- **返回字段**: 标签名称、标签编码、标签层级、数值、均值、环比、同比
- **特点**: 
  - 支持动态标签层级（通过tag1Code、tag2Code等参数）
  - 支持两种数据类型：mention（提及量）和negative_rate（负面率）
  - 负面率时按固定顺序排序：认知、选择、购买、使用、维保、再购

### 8. 高频场景TOP5接口
- **接口路径**: `/journey-analysis/getHighFreqSceneTop`
- **功能**: 统计高频场景TOP5
- **返回字段**: 场景名称、场景编码、提及量、提及量环比、提及量同比、负面率、负面率环比、负面率同比
- **特点**: 按提及量排序，返回TOP5场景

### 9. 飙升场景TOP5接口
- **接口路径**: `/journey-analysis/getSurgingSceneTop`
- **功能**: 统计飙升场景TOP5
- **返回字段**: 场景名称、场景编码、提及量、提及量环比、提及量同比、负面率、负面率环比、负面率同比
- **特点**: 按提及量环比排序，返回TOP5场景

## 技术实现特点

### 1. 架构设计
- 遵循Controller-Service-Mapper三层架构
- 使用MyBatis-Plus进行数据库操作
- 所有SQL逻辑在XML文件中实现

### 2. 计算规范
- **环比计算**: `[(本期值 - 上期值) / 上期值] × 100%`
- **同比计算**: `[(本期值 - 去年同期值) / 去年同期值] × 100%`
- **负面率计算**: `负面数 / 总提及数 * 100%`
- **占比计算**: `当前值 / 总值 * 100%`
- 所有计算结果保留两位小数（四舍五入）

### 3. 性能优化
- 使用WITH子句优化复杂查询
- 合理使用索引字段作为查询条件
- 避免全表扫描，使用分页和LIMIT限制结果集
- 使用LEFT JOIN处理可能为空的关联数据

### 4. 数据安全
- 使用参数化查询防止SQL注入
- 对空值进行合理处理，避免除零错误
- 使用COALESCE和NULLIF函数处理空值情况

## 注意事项

1. **数据源**: 所有接口都基于voc_sentiment_annotations_results_v表
2. **时间范围**: 通过startTime和endTime参数控制查询时间范围
3. **客户类型**: 已更新为新的四种类型（普通用户、车主客户、会员客户、售后客户）
4. **环比同比**: 自动计算上月和去年同期数据进行对比
5. **空值处理**: 对于可能为空的计算结果，返回null而不是错误
