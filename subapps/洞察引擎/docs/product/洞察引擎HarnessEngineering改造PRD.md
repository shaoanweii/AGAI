# 洞察引擎 Harness Engineering 工程化改造 PRD

## 1. 文档说明

### 1.1 文档目标

本文档面向产品、研发、测试、算法、运营和交付团队，定义洞察引擎在不考虑 ChatBI 等前端功能的前提下，围绕 Harness Engineering 进行 AI 工程化改造的产品需求。

本文档重点回答：

1. 现有洞察引擎需要新增哪些 AI 工程化模块。
2. 每个模块包含哪些页面、筛选条件、列表字段和操作。
3. 每个模块如何支持新增、查询、编辑、删除、启停、发布、回滚、审核等产品动作。
4. 模型后处理节点和数据监控能力如何纳入现有业务闭环。
5. 异常、空态、权限、状态流转和验收标准如何定义。

技术架构、数据库表、接口设计、消息队列、调度机制、模型 SDK、权限实现、部署方案不在本文档展开，由技术专家另行输出详细设计。

### 1.2 Harness Engineering 定义

本文中的 Harness Engineering 指围绕 AI 能力构建一套可驾驭、可验证、可复用、可监控、可回滚的工程化体系。它不是单纯调用模型，而是把模型、Prompt、知识、后处理、评测、监控、人工反馈、版本发布和业务结果串成闭环。

在洞察引擎中的具体表现：

- AI 任务可配置。
- Prompt 可版本化。
- 知识检索可管理。
- 模型输出可后处理。
- 结果质量可评测。
- 线上运行可监控。
- 异常结果可告警。
- 人工纠错可回流。
- 版本变更可审计、可灰度、可回滚。

### 1.3 范围说明

纳入本次 PRD：

- AI 任务编排管理。
- Prompt 版本管理。
- 模型配置与调用策略管理。
- 知识检索配置。
- 模型后处理节点管理。
- 后处理流程管理。
- 评测集与评测任务管理。
- AI 结果审核与人工反馈。
- 数据监控中心。
- AI 运行监控。
- 告警规则与告警事件。
- 版本发布与变更审计。

暂不纳入本次 PRD：

- ChatBI 前端问数、会话、报表配置等功能。
- 具体模型训练平台。
- 详细接口协议和数据库设计。
- 数据仓库底层建模细节。
- 模型供应商商务管理。

## 2. 背景与问题

### 2.1 当前项目基础

现有洞察引擎已经具备以下基础：

- 数据治理：原始数据、结果数据查询，新词发现。
- 知识中心：语料映射、关键词库、标准观点、体验代码、属性标签、用车场景、品牌车系。
- 规则引擎：闭环规则、批量事件、规则测试、清洗规则。
- 审核管理：纠错审核。
- 系统设置：账号、角色、下载管理。
- 后端服务：数据集成、分析、洞察、风控、报表、第三方模型服务、向量能力等。

### 2.2 当前缺口

1. 缺少统一 AI 任务管理，模型调用分散，业务难追溯。
2. 缺少 Prompt 版本管理，Prompt 修改后难评估、难回滚。
3. 缺少模型后处理节点，模型原始输出无法稳定转换成业务可用结果。
4. 缺少后处理流程编排，纠错、清洗、归一、置信度修正等逻辑难复用。
5. 缺少评测体系，无法证明模型、Prompt、知识库改动是否有效。
6. 缺少数据监控能力，数据接入、处理、标签、模型输出质量异常无法及时发现。
7. 缺少 AI 运行监控，模型失败率、延迟、成本、采纳率不可视。
8. 缺少人工反馈闭环，审核和纠错数据没有系统化反哺 AI。

## 3. 产品目标

### 3.1 一期目标

1. 建立 AI 工程化控制台，能管理 AI 任务、Prompt、模型、知识检索和后处理流程。
2. 新增模型后处理节点能力，支持对模型输出做结构化、归一化、校验、映射、置信度修正和异常兜底。
3. 新增数据监控中心，监控数据接入、处理、标签质量、模型输出质量和业务指标波动。
4. 建立评测集与评测任务，支持 Prompt、模型、后处理流程上线前评估。
5. 建立人工反馈闭环，把纠错审核、新词处理、人工修正转化为可复用样本。

### 3.2 二期目标

1. 支持 AI 版本灰度、A/B 对比、自动回滚。
2. 支持质量、成本、延迟、采纳率综合看板。
3. 支持规则、标签、观点、场景的 AI 辅助推荐。
4. 支持多客户、多渠道差异化 AI 策略。

## 4. 用户角色与权限

### 4.1 AI 平台管理员

权限：

- 管理模型、Prompt、AI 任务、后处理节点、后处理流程、评测任务。
- 发布、回滚、停用 AI 配置。
- 查看全部运行日志和监控数据。

### 4.2 算法/模型专家

权限：

- 维护 Prompt、模型策略、评测集、评测任务。
- 查看评测结果和模型输出样本。
- 提交发布申请，但不一定具备最终发布权限。

### 4.3 业务运营人员

权限：

- 查看 AI 输出结果。
- 处理新词、纠错、审核、人工反馈。
- 查看与自己客户/渠道相关的数据监控和质量问题。
- 可提出知识、标签、规则修正建议。

### 4.4 数据治理人员

权限：

- 查看数据接入、处理、字段完整性、标签覆盖率等监控。
- 处理数据异常事件。
- 配置数据监控规则。

### 4.5 审核人员

权限：

- 查看待审核 AI 结果和人工纠错。
- 接受、修改、驳回 AI 建议。
- 记录审核原因和反馈标签。

### 4.6 普通查看用户

权限：

- 只查看授权范围内的监控看板和任务结果。
- 无配置、发布、删除权限。

## 6. 通用交互规范

### 6.1 列表页通用能力

每个配置类列表页默认支持：

- 查询。
- 重置。
- 分页。
- 列表刷新。
- 新增。
- 查看详情。
- 编辑。
- 删除。
- 启用/禁用。
- 批量操作。
- 操作日志。
- 导出列表。

如某模块不支持删除，应改为停用、归档或下线。

### 6.2 状态通用定义

| 状态 | 含义 |
| --- | --- |
| 草稿 | 创建后未启用或未提交发布 |
| 待审核 | 已提交，等待审核 |
| 已驳回 | 审核不通过 |
| 待发布 | 审核通过但未正式生效 |
| 灰度中 | 部分流量或部分客户生效 |
| 已发布 | 正式生效 |
| 已停用 | 不再被新任务使用 |
| 已归档 | 历史保留，不可编辑和启用 |
| 异常 | 配置、执行或依赖存在异常 |

### 6.3 高风险操作

以下操作必须二次确认：

- 删除。
- 批量删除。
- 停用已发布配置。
- 发布新版本。
- 回滚版本。
- 清空评测结果。
- 批量接受或驳回 AI 结果。
- 关闭告警规则。

### 6.4 通用异常

| 异常 | 页面表现 | 处理要求 |
| --- | --- | --- |
| 无权限 | 隐藏按钮或展示无权限提示 | 不允许绕过 |
| 查询失败 | 错误提示，保留筛选条件 | 可重试 |
| 保存失败 | 展示失败原因 | 表单不关闭 |
| 删除失败 | 展示引用关系或失败原因 | 不刷新列表状态 |
| 发布失败 | 展示校验不通过项 | 保留草稿 |
| 依赖缺失 | 标识异常状态 | 提供查看依赖入口 |
| 数据为空 | 展示空态 | 有权限时提供新增入口 |

## 7. 模块一：AI 任务管理

### 7.1 模块定位

AI 任务管理用于定义洞察引擎中所有 AI 能力的业务任务，例如标签推荐、观点归一、新词归类、摘要生成、风险判断、规则建议、数据质检等。每个 AI 任务绑定模型、Prompt、知识检索配置和后处理流程。

### 7.2 页面入口

菜单：`AI 工程化 / AI 任务管理`

### 7.3 筛选条件

| 条件 | 类型 | 说明 |
| --- | --- | --- |
| 任务名称 | 输入框 | 支持模糊搜索 |
| 任务编码 | 输入框 | 精确或模糊搜索 |
| 任务类型 | 下拉 | 标签推荐、观点归一、摘要生成、风险判断、数据质检、规则建议、其他 |
| 适用客户 | 多选下拉/树 | 按用户权限展示 |
| 适用渠道 | 多选级联 | 渠道树 |
| 状态 | 多选 | 草稿、已发布、灰度中、已停用、异常 |
| 模型名称 | 下拉 | 已配置模型 |
| Prompt 名称 | 下拉 | 已配置 Prompt |
| 创建人 | 下拉/输入 | 支持搜索 |
| 更新时间 | 日期范围 | 按更新时间筛选 |

### 7.4 列表字段

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 业务可读名称 |
| 任务编码 | 系统唯一编码 |
| 任务类型 | AI 任务分类 |
| 适用客户 | 客户范围，过多时展示数量 |
| 适用渠道 | 渠道范围，过多时展示数量 |
| 当前模型 | 已绑定模型 |
| Prompt 版本 | 当前生效版本 |
| 后处理流程 | 当前绑定流程 |
| 知识检索 | 是否启用检索 |
| 状态 | 当前任务状态 |
| 今日调用量 | 当日执行次数 |
| 今日成功率 | 当日成功/总调用 |
| 最近发布时间 | 最后一次发布 |
| 更新人 | 最后更新人 |
| 更新时间 | 最后更新时间 |
| 操作 | 详情、编辑、复制、发布、停用、删除、运行日志 |

### 7.5 新增任务

字段：

- 任务名称，必填。
- 任务编码，必填，唯一。
- 任务类型，必填。
- 任务描述，选填。
- 适用客户，必填。
- 适用渠道，选填。
- 输入数据类型，必填：原始文本、结果数据、标签数据、规则数据、监控数据、其他。
- 输出结果类型，必填：标签、观点、摘要、风险等级、结构化 JSON、质检结果、其他。
- 绑定模型，必填。
- 绑定 Prompt，必填。
- 绑定知识检索配置，选填。
- 绑定后处理流程，选填但建议必填。
- 失败兜底策略，必填：返回空、返回原始结果、返回默认结果、转人工审核。
- 是否记录样本，必填。
- 是否进入人工审核，必填。
- 备注，选填。

校验：

- 任务编码唯一。
- 已停用模型不可绑定。
- 已停用 Prompt 不可绑定。
- 后处理流程输出类型必须与任务输出结果类型兼容。

### 7.6 编辑任务

可编辑字段：

- 任务名称。
- 任务描述。
- 适用客户/渠道。
- 绑定模型。
- 绑定 Prompt。
- 绑定知识检索配置。
- 绑定后处理流程。
- 失败兜底策略。
- 是否记录样本。
- 是否进入人工审核。

不可编辑字段：

- 任务编码。
- 已有历史运行记录的任务类型原则上不可修改，如需修改应复制新任务。

### 7.7 删除任务

规则：

- 草稿且无运行记录可删除。
- 已发布、灰度中、有运行记录的任务不可删除，只能停用或归档。
- 被其他流程引用的任务不可删除。

### 7.8 复制任务

复制内容：

- 基础配置。
- 模型绑定。
- Prompt 绑定。
- 知识检索配置。
- 后处理流程。
- 兜底策略。

复制后：

- 新任务状态为草稿。
- 任务名称默认追加“副本”。
- 任务编码必须重新填写。

### 7.9 异常场景

| 场景 | 处理 |
| --- | --- |
| 模型已停用 | 任务状态标记异常，不允许发布 |
| Prompt 版本已下线 | 任务状态标记异常，提示更换版本 |
| 后处理流程缺失节点 | 不允许发布 |
| 知识检索配置不可用 | 可发布但提示风险，按业务配置决定是否阻断 |
| 今日成功率低于阈值 | 列表标红并进入运行监控 |

### 8.6 版本管理

每次保存可生成新版本：

- 版本号。
- 版本说明。
- 变更原因。
- 创建人。
- 创建时间。
- 评测状态。
- 发布状态。

操作：

- 查看版本详情。
- 对比两个版本差异。
- 基于历史版本创建新草稿。
- 提交审核。
- 发布。
- 回滚。

### 8.7 删除规则

- 已被任务引用的 Prompt 不可删除。
- 已发布版本不可物理删除，只能停用或归档。
- 草稿版本可删除。

### 8.8 异常场景

| 场景 | 处理 |
| --- | --- |
| 变量未定义但内容中引用 | 保存失败 |
| 必填变量无示例 | 警告，不阻断 |
| 输出格式为空 | 保存失败 |
| 发布前未评测 | 按权限配置决定阻断或强提示 |
| 正被运行任务使用 | 停用前提示影响范围 |

| 灰度失败率升高 | 触发告警，可暂停或回滚 |
| 回滚失败 | 标记严重告警 |

## 22. 与现有模块的联动

### 22.1 数据治理联动

- 数据查询详情展示 AI 任务结果、后处理结果、置信度和证据。
- 新词发现可把未命中标签、未归一观点转为反馈样本。
- 原始数据和结果数据异常进入数据监控。

### 22.2 知识中心联动

- 标准观点、关键词、体验代码、属性标签、用车场景、品牌车系可作为知识检索来源。
- AI 结果审核中的人工修改可反向产生知识优化建议。
- 后处理节点可引用标签、观点、场景等知识配置。

### 22.3 审核管理联动

- 纠错审核结果进入人工反馈库。
- AI 低置信结果进入 AI 结果审核。
- 审核通过和修改通过可进入评测集候选。

### 22.4 规则引擎联动

- 后处理节点可执行业务规则校验。
- 规则测试结果可作为评测样本。
- 规则命中异常进入数据监控。

### 22.5 下载管理联动

- 数据监控明细、评测报告、运行日志、告警事件支持导出。
- 导出任务进入现有下载管理。

## 23. 非功能性产品要求

### 23.1 权限

- 所有菜单、按钮、数据范围必须受角色权限控制。
- 客户、渠道、部门数据隔离。
- 发布、回滚、删除、强制发布需要高权限。

### 23.2 数据安全

- 输入输出摘要默认脱敏。
- 手机号、VIN、姓名、账号等敏感字段默认不可明文展示。
- 导出需记录审计。

### 23.3 可追溯

任意 AI 业务结果至少可追溯：

- AI 任务。
- 模型。
- Prompt 版本。
- 知识检索配置。
- 后处理流程和节点。
- 运行日志。
- 人工审核或反馈。

### 23.4 可回滚

以下对象发布后必须支持回滚：

- Prompt。
- AI 任务配置。
- 后处理流程。
- 知识检索配置。

## 24. 验收标准

### 24.1 模型后处理节点

1. 可新增、编辑、启用、禁用、复制、删除后处理节点。
2. 可配置不同类型节点的业务规则。
3. 可测试节点输入输出。
4. 节点可被后处理流程引用。
5. 被引用节点不可直接删除。
6. 节点异常时能在流程和监控中体现。

### 24.2 后处理流程

1. 可编排多个节点。
2. 可测试完整流程。
3. 可发布、回滚、停用。
4. 可绑定 AI 任务。
5. 流程执行结果可追溯到每个节点。

### 24.3 数据监控

1. 可查看数据接入、字段质量、标签质量、模型输出、后处理质量监控。
2. 可筛选客户、渠道、时间、任务、模型等条件。
3. 可查看异常样本。
4. 可创建告警规则。
5. 可处理告警事件。

### 24.4 评测体系

1. 可维护评测集。
2. 可创建评测任务。
3. 可查看评测结果和错误样本。
4. 发布前可关联评测结果。

### 24.5 人工反馈

1. AI 结果可进入审核队列。
2. 审核支持通过、修改通过、驳回。
3. 人工结果可进入反馈库。
4. 高质量反馈可加入评测集。
