# 数据洞察引擎需求规格说明书

## 1. 文档目标

本文档用于完整描述“数据洞察引擎”的产品目标、业务对象、角色权限、页面功能、接口边界、数据流、异常处理与验收标准。后续将本文档交给 AI 或研发团队时，应能复刻出与当前项目一致的核心功能形态。

本文档依据当前代码库整理：

- 前端：`前端`，Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus。
- 后端：`后端`，Java 17 + Spring Boot + Spring Cloud + Gradle 微服务体系。
- 主要业务接口前缀：`/insights/*`，另有 `/auth/*`、`/report/*`、`/ai/*`、`/new-words/*`。

## 2. 产品定位

数据洞察引擎是面向车企、客户体验、客服运营、质量风险与市场洞察团队的 VOC 管理后台。系统围绕“多渠道客户声音数据”完成数据接入、治理、知识配置、规则处理、人工审核、风险预警、报表分析与权限管理，支持企业把非结构化文本、问卷、舆情、客服、CRM 等数据转化为可查询、可追踪、可复用、可决策的洞察资产。

## 3. 核心目标

1. 汇聚多渠道客户声音数据，形成统一数据资产。
2. 对原始文本进行清洗、标签化、情感/意图/关键词/观点识别。
3. 管理业务知识库，包括语料映射、关键词、标准观点、体验代码、属性标签、用车场景、品牌车系。
4. 通过规则引擎完成单点事件、批量事件、清洗规则的配置、测试与启停。
5. 支持人工纠错、审核与标签修正，形成可追踪闭环。
6. 支持账号、角色、菜单、按钮、客户、部门、下载任务等系统管理能力。
7. 支持后端报表、ChatBI、移动报表、风控分析、数据集成等扩展服务接入。

## 4. 用户角色

### 4.1 超级管理员

- 管理客户、账号、角色、菜单权限、按钮权限、部门权限、渠道权限。
- 查看全部客户/项目/渠道/知识库/规则/下载任务。
- 配置系统级基础数据，如品牌、车系、车企、渠道、标签目录。

### 4.2 运营管理员

- 管理数据查询、知识中心、规则引擎、审核管理。
- 可新建、编辑、启停、复制、删除业务规则和知识项。
- 可导出原始数据、结果数据、纠错数据。

### 4.3 审核人员

- 查看待审核纠错记录。
- 审核通过或驳回标签纠错。
- 查看纠错详情和历史记录。

### 4.4 分析人员

- 查询原始数据和结果数据。
- 按渠道、项目、品牌、车系、区域、时间、标签等条件筛选数据。
- 使用报表、ChatBI、风险分析能力输出业务洞察。

### 4.5 普通查看用户

- 只能访问授权菜单。
- 只能查看授权客户、渠道、部门和数据范围。
- 无新增、编辑、删除、导出等敏感操作，除非按钮权限单独授权。

## 5. 权限模型

### 5.1 认证

- 本地开发环境提供 `/login` 页面。
- 非开发环境无 Token 时跳转统一 SSO 地址。
- 登录成功后本地保存：
  - `TOKEN_KEY`：访问 Token。
  - `USER_NAME_KEY`：用户名称。
  - `USER_ID_KEY`：用户 ID 或工号。
- 请求头携带：`Authorization: Bearer <access_token>`。

### 5.2 菜单权限

- 后端接口 `/insights/userPermissions` 返回用户菜单与按钮权限。
- 菜单项的 `permissionKey` 必须与前端动态路由 `name` 一致。
- 前端根据后端菜单过滤 `dynamicRoutes`，只展示授权菜单。
- 无菜单权限时进入 `/redirect`。

### 5.3 按钮权限

- 前端存在 `auth` 指令与按钮权限集合 `buttonPerm`。
- 新增、编辑、删除、导出、启停、复制、审核等操作应按按钮权限控制。

### 5.4 数据权限

- 用户权限返回 `clientIds`、`defaultClientId`、`isAdmin`。
- 查询、配置、导出均应默认带入当前客户或授权客户范围。
- 部门-账号树由 `/insights/accountInfo/findDepartAccountTree` 获取，并在 Pinia 中缓存。

## 7. 功能需求

### 7.1 登录与访问控制

#### 页面

- 本地开发：`/login`
- 统一认证：非开发环境跳转 SSO。

#### 功能

- 输入账号、密码、验证码或校验参数完成登录。
- 登录前对用户名和密码进行加密处理。
- 登录成功后拉取用户权限并生成动态菜单。
- Token 失效、接口鉴权失败或权限加载失败时返回登录/SSO。
- 支持退出登录，调用 `/insights/logout` 后清除本地身份信息。
- 支持前端版本检测：当 `/ins/version.json` 版本变化时刷新页面。

#### 验收标准

- 无 Token 访问业务页时不允许进入。
- 登录后只能看到有权限的菜单。
- 后端菜单顺序应决定前端菜单展示顺序。
- 退出后再次访问业务页必须重新认证。

### 7.2 主控台

#### 路由

- `/home`

#### 功能

- 作为系统首页，承载业务概览入口。
- 可展示数据总览、任务概览、风险概览、待办、快捷入口等信息。
- 当前前端路由将根路径 `/` 重定向至 `/home`。

#### 验收标准

- 登录后默认进入主控台。
- 主控台菜单在任何用户有基础访问权限时均可见。

### 7.3 数据治理

#### 7.3.1 数据查询

路由：`/dataCenter/dataQuery`

Header 页签：

- 结果数据
- 原始数据

核心功能：

- 按当前页签查询结果数据或原始数据。
- 支持渠道、项目、品牌、车系、区域、标签、时间、关键词等组合筛选。
- 支持表格列表、分页、详情查看。
- 支持原始数据导出：`/insights/insCqCaDataSource/exportRawData`。
- 支持结果数据导出：`/insights/insCqCaDataSource/exportRawDataResult`。
- 支持下载任务进入系统设置的下载管理查看。

数据对象：

- 原始数据：数据 ID、渠道、原文、发布时间、抓取时间、账号、品牌车系、地区等。
- 结果数据：原始数据字段 + 标签、情感、意图、关键词、观点、体验代码、风险信息、处理状态等。

验收标准：

- 切换“结果数据/原始数据”后查询条件与列表口径同步切换。
- 导出应异步生成下载任务，不阻塞页面。
- 查询必须受客户、渠道、部门、角色权限限制。

#### 7.3.2 新词发现

路由：`/dataCenter/discovery`

Header 页签：

- 文本新词
- 问卷新词

核心功能：

- 查询新词列表：`/insights/words/queryWordsInfo`。
- 查询新观点/问卷观点：`/insights/opinions/queryOpinionsInfo`。
- 获取标签类型：`/insights/words/getTagType`。
- 获取标签目录树：`/insights/words/findTagLibCategoryTree`。
- 分配文本新词：`/insights/words/allocationWords`。
- 分配观点：`/insights/opinions/allocationOpinions`。
- 将新词加入风险关键词库：`/insights/keywords/addRisKeywords`。
- 支持详情弹窗查看新词上下文与归属。

业务规则：

- 文本新词与问卷新词数据源不同，但交互一致。
- 新词可分配到标签体系或知识库条目。
- 已处理的新词应更新状态，避免重复分配。

验收标准：

- 新词列表支持筛选、分页、详情、分配。
- 分配后列表状态即时刷新。
- 标签树为空或无权限时提示明确。

- 支持新增、编辑、删除、查询、启停。

验收标准：

- 语料映射必须能绑定客户、渠道、标签目录。

#### 7.4.3 标准观点

路由：`/knowledgeCenter/standardPoint`

核心功能：

- 维护标准化观点表达。

- 支持与标签、体验代码、场景关联。

关联 AI 能力：

- `/ai/opinion-synonyms` 用于观点同义词创建和更新。

验收标准：

- 标准观点可被新词发现、规则测试、数据处理结果引用。
- 同义观点应能归一到同一标准观点。

#### 7.4.4 体验代码

路由：`/knowledgeCenter/experienceCode`

核心功能：

验收标准：

- 编码应唯一。
- 父子层级变更后级联选择器与列表同步刷新。

验收标准：

#### 7.4.7 品牌车系

路由：`/knowledgeCenter/brandSeries`

Header 页签：

- 车系管理
- 品牌管理
- 车企管理

接口范围：

- 车企：`/insights/automark/*`
- 品牌：`/insights/brandInfo/*`
- 车系：`/insights/carSeriesInfo/*`

核心功能：

- 车企管理：车企分页查询、新增、编辑、详情、启停、渠道树、标签目录树。
- 品牌管理：品牌分页查询、新增、编辑、删除、详情、启停、渠道树。
- 车系管理：车系分页查询、新增、编辑、删除、详情、启停、品牌关联。

业务规则：

- 车企 > 品牌 > 车系是层级关系。
- 品牌必须归属车企。
- 车系必须归属品牌。
- 禁用上级对象后，下级对象在选择器中应不可用或提示受限。

验收标准：

- 三个页签切换不丢失各自查询状态。
- 新增/编辑表单必须校验必填、编码唯一和层级关系。

- 纠错详情：`/insights/addLabel/queryCorrectionInfo`

- 删除启用中规则需阻断或要求先禁用。

### 7.7 系统设置

#### 7.7.1 账号管理

路由：`/settings/accountManagement`

接口：

- 查询账号：`/insights/accountInfo/findAccountInfo`
- 新增账号：`/insights/accountInfo/saveAccountInfo`
- 更新账号：`/insights/accountInfo/updateAccountInfo`
- 角色列表：`/insights/accountInfo/queryRoleALlList`
- 部门列表：`/insights/accountInfo/findDepartList`
- 部门树：`/insights/accountInfo/findDepartTree`
- 部门-账号树：`/insights/accountInfo/findDepartAccountTree`
- 指定部门账号：`/insights/accountInfo/findAccountByDeptId`
- 客户查询：`/insights/customer/findCustomerInfo`
- 客户新增/更新/编码校验：`/insights/customer/*`

核心功能：

- 账号列表查询、分页。
- 新增、编辑账号。
- 绑定角色、部门、客户、渠道权限。
- 查看部门-账号树。
- 支持账号状态管理。

验收标准：

- 账号保存必须校验用户名/工号/邮箱/手机号规则。
- 角色为空时应阻止保存或提示权限不完整。
- 管理员可配置客户范围，普通管理员只能配置授权范围内账号。

#### 7.7.2 角色管理

路由：`/settings/role`

接口：

- 角色详情：`/insights/role/queryRoleInfo`
- 菜单权限树：`/insights/role/queryMenuPermissionList`
- 保存/更新角色：`/insights/role/saveOrUpdateRole`
- 用户角色列表：`/insights/role/getUserRoleList`

核心功能：

- 角色列表查询。
- 新增、编辑角色。
- 配置菜单权限、按钮权限。
- 配置角色适用客户或数据范围。

验收标准：

- 角色名在客户范围内唯一。
- 菜单权限与按钮权限保存后，重新登录或刷新权限后生效。

#### 7.7.3 下载管理

路由：`/settings/download`

接口：

- 下载任务列表：`/insights/downLoad/findDownLoadFileList`
- 重新下载：`/insights/downLoad/downloadAgain`
- 下载文件：`/insights/downLoad/downloadFile`
- 可见用户列表：`/insights/downLoad/findVisibleUserList`

核心功能：

- 查询导出任务列表。
- 查看任务状态、创建人、创建时间、文件名、文件大小。
- 下载已完成文件。
- 失败任务可重试。
- 管理任务可见范围。

验收标准：

- 未完成或失败任务不可直接下载。
- 下载失败时展示明确错误信息。
- 用户只能看到自己或授权可见的下载任务。

## 10. 通用交互规则

1. 查询区位于列表上方，使用表单布局，支持重置和查询。
2. 列表使用 Element Plus 表格，表头浅灰背景，右下角分页。
3. 新增/编辑使用弹窗或抽屉。
4. 删除、退出、批量启停、审核通过/驳回等高风险操作必须二次确认。
5. 接口成功使用成功提示，失败使用错误提示。
6. 空数据展示空态图或“暂无数据”。
7. 导出操作生成异步下载任务，用户到下载管理查看。
8. 所有列表页应支持 loading 态。
9. 所有表单保存前必须做必填、长度、格式、业务唯一性校验。
10. 批量操作必须在至少选中一条记录后才可执行。

## 11. 非功能需求

### 11.1 性能

- 菜单权限、部门账号树等基础数据应缓存，避免重复请求。
- 大树组件使用懒加载。
- 列表接口必须分页。
- 导出任务异步化。
- StarRocks 查询需按时间、客户、渠道、品牌等高频维度建立分区、索引或物化视图。

### 11.2 安全

- Token 统一从请求拦截器注入。
- 敏感字段如手机号、姓名、VIN、账号应按权限脱敏。
- 导出必须记录审计日志。
- 高风险配置变更记录操作人、操作时间、变更前后值。
- 文件上传限制类型、大小并做安全扫描。

### 11.3 可用性

- 支持 SSO 与本地开发登录双模式。
- 接口异常不应导致页面白屏。
- 权限为空应进入明确提示页。
- 前端版本更新后自动刷新。

### 11.4 可维护性

- 前端 API 按业务域拆分。
- 路由 `name` 与权限 `permissionKey` 保持一一对应。
- 后端服务按 app、service、component 分层。
- 配置通过 Nacos/profile 管理。

## 12. AI 复刻提示词摘要

如果把本系统交给 AI 重新实现，应至少给出以下约束：

1. 构建一个 Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus 的 VOC 管理后台。
2. 使用左侧菜单、顶部 Header、主内容区布局；菜单来自后端权限，路由 name 与 permissionKey 匹配。
3. 实现菜单：主控台、数据治理、知识中心、审核管理、规则引擎、系统设置。
4. 数据治理含结果/原始数据查询和文本/问卷新词发现。
5. 知识中心含语料映射、关键词库、标准观点、体验代码、属性标签、用车场景、品牌车系。
6. 审核管理含纠错审核。
7. 规则引擎含单点事件、批量事件、规则测试、清洗规则。
8. 系统设置含账号管理、角色管理、下载管理。
9. 所有列表页具备查询、重置、分页、loading、空态、权限按钮、导出或批量操作能力。
10. 后端采用 Spring Boot 微服务，服务包括 auth、security、insights、analysis、risk、report、data-integration、chat-bi、third、bizlogs。
11. 数据底座包括 MySQL、Redis、Kafka、StarRocks、Milvus、MinIO、XXL-Job。
12. VOC 宽表字段覆盖数据、渠道、品牌车系、客户、车辆、经销商、AI 结果、多级标签、时间维度。
